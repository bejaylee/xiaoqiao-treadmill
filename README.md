# 小乔 SmartRun 跑步机 · 离线自研控制端

> **兼容范围（必读）**：原厂 App 面向**多款**小乔跑步机，但本项目**只在作者自有的一台型号上做过端到端实测**
> （`factory=1` / `model=13` / MAC `[MAC 已脱敏]` / WiFi 固件 `30`）。
> **不要假定其它型号兼容**——详见下面的「兼容性与实测范围」。

> 厂家服务器停摆、原 App 失效后，恢复被云端带走的智能控制能力：完全离线、不登录、不依赖任何云端，
> 用逆向还原的局域网协议重建控制 App + 配网工具 + PC 验证脚本。
> **跑步机面板本身仍可完成基本运动操作**，本项目补回的是手机端控制、课程、记录等被 App 停服影响的部分。

## 兼容性与实测范围（重要）

原厂 App（`com.qiaosports.xqiao` v2.0.3）**不是只为一款跑步机写的**。静态分析能看到这些多型号痕迹：

| 证据 | 位置 / 内容 |
|---|---|
| 云端按型号校验 | `DeviceSearchActivity.verifyDevice()` 把广播解出的 `factory`、`model`、`MAC` 组成 `CheckMacBody.type / vendor / mac` 发给服务端 `macCheck`，由**服务端白名单**决定设备是否合法——机型清单不在 APK 里 |
| 双型号字段 | 配网用 `DeviceInfo.model` 写死 `XQIAO_HEALTH_RUNNINGMACHINE_XQIAO_001`；Alink 配网配置同时有 `model` 与 `modelX` 两个字段，`shouldFilterModel` 打开时会用两者一起过滤 |
| 两套配网协议 | 阿里云 Alink SDK 的接收分支明确区分 `"1.1"` 与 `"1.6"`：`1.1` 额外校验 `macAddr`，`1.6` 只校验型号 |
| 两种控制面板 | 资源文案同时提到按键面板（按住面板 `−` 键 5 秒）和**旋钮机型**（拔掉安全锁后按住旋钮 5 秒） |
| 多个商品名痕迹 | 资源里有 `XQIAO001` 字样、`XQIAO_HEALTH_RUNNINGMACHINE_XQIAO_001` 产品 ID |

**但请注意：这些只说明原 App 有覆盖多款机型的框架，不能推出本项目支持全部型号。**

本项目**唯一实测**的设备是：

| 项 | 值 |
|---|---|
| UDP 广播 | `factory=1`、`model=13`、Magic `XJXQ` |
| MAC | `[MAC 已脱敏]` |
| WiFi 模块固件 | `30` |
| 局域网 IP | `192.168.100.178` |
| 实测内容 | 配网、发现、连接、调速、安全停机、课程下发、状态帧、语音、记录、分享卡、真人上跑带全流程 |

也就是说：**协议栈的其它分支（model 值不同、配网协议 1.6、旋钮机型、其它固件）只是从原 App 静态推断，未做真机验证。**
如果你手上是别的型号，请先按 [PROTOCOL.md](PROTOCOL.md) 抓广播和状态帧核对字段，再空载试控制命令；
不同型号可能改了帧长、状态字段偏移、速度上限，甚至坡度控制。

## 为什么做这个项目

我有一台**小乔 SmartRun WiFi 跑步机**。机器本身没坏——**面板仍能完成开关机、调速和基本跑步**。
坏掉的是手机那一半：官方 App（`com.qiaosports.xqiao` v2.0.3）依赖厂商服务器，
服务器一停，配网、课程、记录、排行榜等功能全部失效，App 连不上设备。
本项目要恢复的是这部分**智能控制与数据能力**，不是让一台不能动的机器重新动起来。

逆向分析后发现一个关键事实：**这台跑步机根本不是蓝牙设备，而是一个局域网设备**。
控制协议完全在本地：

- 跑步机每 1–2 秒向 UDP **19032** 广播设备信息（Magic `XJXQ`）；
- 手机连跑步机 IP 的 TCP **12304**，发自定义二进制帧控制速度、开关机、下发课程；
- 跑步机主动推送 34 字节状态帧（速度 / 时长 / 里程 / 热量 / 心率 / 步数）。

也就是说，**只要把这份本地协议重写一遍，就不需要厂商的任何东西**。
本项目就是这个过程的结果：从 APK 静态分析 → 协议逐字节还原 → PC 端验证 → Android App → 真人上跑带实测。

### 项目原则

1. **只恢复基本控制**：调速、开关机、课程、状态读取、配网。
2. **不碰固件升级通道**（原 App 的 `FirmwareUpgradeActivity` 走 UDP 传固件，刷坏不可恢复）。
3. **不绕过任何在线授权**，不做卡密/激活相关的事；协议全部来自本地流量与静态分析。
4. **离线优先**：无账号、无云同步、无遥测；所有数据只存本机。

## 协议速览

| 项 | 值 |
|---|---|
| 发现 | UDP 19032 广播，30 字节，Magic `XJXQ` |
| 控制 | TCP 12304，帧格式 `[type][len][payload][chk2][CRLF]` |
| 校验 | `sum(payload) & 0xFFFF`，大端 |
| 心跳 | 每 5 秒 `04 01 00 00 00 0D 0A` |
| 状态帧 | 34 字节，速度 / 时长 / 里程 / 热量 / 心率 / 步数 / 电源状态 |
| 里程单位 | 0.01 km（10 米）/ 单位 |
| 电源位 | 0 待机 / 1 开机 / 2 运行 / 3 停止中 |
| 坡度 | 该型号不支持 |

逐字节推导与证据见 [PROTOCOL.md](PROTOCOL.md)。

## 构建

不需要 Android Studio。需要 JDK 17 + Android build-tools 34 + platform android.jar。

```bash
cd android
bash build_apk.sh debug     # 调试包（Android Debug 证书）
bash build_apk.sh release   # 发布包（需要自己的 release.keystore）
```

构建流程：课程库生成 → **协议单测（18 项）** → aapt2 资源 → javac → d8 → zipalign → apksigner。
版本号单一来源为仓库根目录 `version.txt`。

## 配网

原 App 一死，最卡的就是让跑步机重新连上 WiFi。还原结果是 **ESP-Touch v2（乐鑫 SmartConfig）**，
纯本地广播、不依赖厂商服务器。跑步机待机时长按面板「−」键 5 秒进入配网态，然后：

```bash
cd tools
python xq_provision.py --ssid "家里的2.4G" --password "12345678"
```

注意：ESP 模块只收 **2.4 GHz**，电脑/手机必须连 2.4G。完整过程见 [PROVISION.md](PROVISION.md)。

## 安全须知

1. **先空载验证**速度命令，人不要站在跑带上。
2. **`off`（cmd=1, data=1）是切断动力**，不是暂停；真人在跑带上时不要用 `off` 当暂停键。
3. 测试期间务必夹好**物理急停夹 / 安全锁**。
4. **不要碰固件升级通道**，刷坏无法恢复。
